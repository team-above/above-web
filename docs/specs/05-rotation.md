# 05. 사진 자유 회전

- 상태: **Implemented** (2026-07-28)
- ⚠ 회전 입력은 [스펙 06](06-selection.md)이 대체 (2026-07-28): 트위스트(두 손가락 회전) 제거 —
  실기기에서 핀치와 충돌. 회전은 선택 후 궤도 핸들(⟳), Shift+휠은 데스크톱 보조로 유지.
  저장 구조도 초점(focal)·줌·회전 모두 슬롯 공유로 재편(스펙 06)
- 변경 (2026-07-28, 2차): **회전은 슬롯 사진의 공유 속성** — 비율(post/story) 전환에도 유지된다.
  위치·배율 조정값은 기존대로 비율별 독립(스펙 03 AC5). 저장 구조: rotations[slotId] 공유 +
  transforms[variant][slotId]={x,y,scale}, 렌더·제스처는 둘을 합성(composeTransform)해 항상 클램프
- 구현 노트: transform을 슬롯 중심 기준 {x,y,scale,rotation}으로 재정의(스펙 03 모델 대체).
  회전 E2E는 Shift+휠(90° 스냅)로 내보내기 픽셀까지 검증, 트위스트는 각도 계산이 동일 코드 경로.
  자유 각도(40°) 슬롯 모서리 무빈틈은 픽셀 프로브로 확인
- 관련: [스펙 03](03-editor.md)(사진 조작·클램프 모델 확장), 기획 요청 2026-07-28 — "90° 단위가 아닌
  사용자 마음대로 회전"

## 배경 / 목적

슬롯 안 사진을 임의 각도로 회전할 수 있게 한다. 회전 중에도 기존 불변식
**"사진이 슬롯을 빈틈 없이 덮는다(cover)"**는 유지되어야 한다 — 인스타그램 등 표준 에디터처럼
**회전하면 필요한 만큼 자동으로 확대**되는 방식으로 해결한다.

## 조작 방식

- **모바일**: 두 손가락 트위스트 — 기존 핀치 제스처에 회전이 자연 결합 (두 손가락 각도 변화 = 회전,
  거리 변화 = 줌, 동시 적용)
- **데스크톱**: (확인 필요 — 아래 질문) 제안은 **Shift+휠 = 회전**. 선택 상태·부가 UI 없이
  기존 직접 조작 모델과 일관
- 회전 중에도 고스트(35%)가 실제 회전 상태로 보인다 (기존 메커니즘 자동 적용)

## 변환 모델 확장

transform을 **슬롯 중심 기준**으로 재정의한다:

```jsonc
{
  "x": 0, // 사진 중심의 슬롯 중심 대비 오프셋 (canvas px)
  "y": 0,
  "scale": 1, // 원본 대비 배율
  "rotation": 0, // 라디안, 사진 중심 기준 회전
}
```

### 불변식 유지 수학 (순수 함수, 커버리지 100% 유지)

- **각도별 최소 배율**: 슬롯 rect(W×H)를 각도 θ로 회전한 사진(w×h)이 덮으려면
  `minScale(θ) = max((W·|cosθ|+H·|sinθ|)/w, (W·|sinθ|+H·|cosθ|)/h)`
- **회전 → 자동 확대**: 회전으로 minScale(θ)가 현재 scale을 넘으면 scale을 그 값으로 올린다
  (반대로 회전을 되돌려도 자동 축소는 하지 않는다 — 사용자가 키운 배율 존중)
- **오프셋 클램프**: 오프셋을 사진 로컬 좌표계로 회전 투영해
  `|o_local| ≤ (사진 반너비·반높이) − (rect의 로컬 투영 반너비·반높이)` 범위로 자른 뒤 되돌린다
- 줌·드래그의 기존 동작(포커스 고정 줌, 캔버스 좌표 드래그)은 회전과 독립적으로 유지

## 스냅 (확인 필요 — 아래 질문)

제안: 0°/90°/180°/270° 근처 ±3°에서 자석 스냅 — "대충 수평으로 되돌리기"가 쉬워진다.
스냅 순간에도 자유 각도로 다시 벗어날 수 있다.

## 수용 기준

1. 두 손가락 트위스트로 임의 각도 회전, 회전 중·후에도 슬롯에 빈틈이 없다 (단위: minScale·클램프
   경계값, E2E: 회전 후 슬롯 가장자리 픽셀 검사)
2. 회전하면 필요한 만큼 자동 확대된다 (단위 테스트)
3. 회전 상태가 내보내기 PNG에 그대로 반영된다 (E2E: 회전 후 다운로드 픽셀 검사)
4. 비율 전환·홈 복귀 초기화 등 기존 상태 규칙에 rotation이 함께 따른다
5. 기존 무회전 플로우(드래그·줌·고스트·커서)가 회귀 없이 동작한다 (기존 E2E 전부 통과)

## 테스트 계획

- 단위: minScale(θ) 경계값(0°/45°/90°/비정방 사진), 회전 자동 확대, 로컬 클램프, 스냅
- E2E: 회전 시뮬레이션은 두 포인터 이벤트 합성이 어려우므로 **스토어 API 주입으로 회전 상태를
  만들고** 렌더·내보내기 픽셀을 검사, 트위스트 제스처 자체는 단위(각도 계산 함수)로 검증

## 사용자 확인 결과 (2026-07-28)

1. **데스크톱 = Shift+휠**, 모바일 = 두 손가락 트위스트 (핀치와 동시 동작)
2. **90° 부근 자석 스냅(±3°) 포함**
