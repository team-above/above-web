## 배경 / 목적

디자이너 시안은 "슬롯 영역을 회색 자리표시로 칠한 통짜 불투명 PNG"다 (2160×2700 / 2160×3840, 알파 없음 — 분석 확인).
시안 6종을 분석한 결과, 단순 "배경 + 사각 슬롯" 모델로는 부족하다:

- **frame02**: 슬롯 2개 — 하단 사각 + 상단 별무리(비사각 마스크, 서로 다른 사진). 파란 별 장식은 사진 **위**
- **frame03**: 독립 슬롯 2개 — 상단 소형 + 하단 대형 (회전 없음, 샘플의 회전은 사용자가 넣은 사진 자체)
- **frame04**: 요일 라벨(흰 텍스트)이 사진 **위**에 얹힘, 둥근 모서리 클리핑. 자리표시의 그라디언트는
  빈 슬롯 스타일이며 사진 위에는 남지 않는다 (Sample04 확인)
- **frame05**: 낙서 스트로크가 슬롯 경계를 넘어 사진 **위**로 겹침

따라서 스키마는 **레이어 모델**과 **파생 에셋 규약**을 정의한다.

## 렌더링 모델 (z-순서)

```
[3] overlay.png   — 시안에서 자리표시 회색을 투명으로 뚫은 파생 PNG (장식·라벨·낙서 포함)
[2] (사용자 사진들) — placement 단위로 배치·마스크 클리핑
[1] base.png      — 원본 시안 그대로 (0.5 다운스케일). 빈 슬롯은 시안의 자리표시가 그대로 보인다
```

- base가 원본 시안 그대로이므로 **빈 슬롯 상태(frame04 "그대로 노출" 확정)가 별도 처리 없이 재현**되고,
  사진이 채워지면 base의 자리표시는 사진에 완전히 가려진다
- 미리보기와 내보내기는 동일한 Konva 씬 그래프로 이 3층을 렌더한다 (AGENTS.md 원칙)
- 사진이 없는 슬롯의 "탭해서 추가" 안내는 UI 레이어로만 표시 (내보내기에서 제외)
- **좌표계 = 내보내기 규격** (post 1080×1350, story 1080×1920). 파생 시 원본 2160대비 0.5 다운스케일 —
  런타임 에셋 용량 절감(모바일 로딩) 겸 좌표계 단일화

## 에셋 파생 규약 (빌드 타임 스크립트)

원본 시안(`docs/design/frames/FrameNN_{post,story}.png`)에서 스크립트로 생성:

1. **base PNG**: 원본을 0.5 다운스케일 → `public/frames/frameNN/{post,story}/base.png`
2. **overlay PNG**: 자리표시 픽셀(무채색 && 밝기 중간 대역 — frame04 그라디언트 포함, 흰 배경·흰 라벨·
   검정 텍스트 제외)을 투명 처리 → `overlay.png`
3. **슬롯 마스크·좌표**: 자리표시 영역의 연결 성분을 분석해 슬롯으로 그룹핑(스크립트 내 프레임별 설정),
   슬롯별 바운딩 박스를 템플릿 JSON에 기록하고 **모든 placement에 마스크 PNG를 생성**한다
   (`mask-<slotId>.png` — 사각/라운드/별무리를 단일 경로로 처리)
4. 파생 스크립트는 저장소에 포함(`scripts/derive-frames.ts`, 순수 로직은 `src/lib/frame-derive.ts`)해
   시안 교체 시 재생성 가능하게 한다

경계 안티앨리어싱 완화를 위해 판정은 색 거리 임계값으로 하고, 결과는 시각 회귀로 검증한다.

## 템플릿 JSON 스키마 (초안)

`src/templates/frameNN.json` — post/story 두 변형을 하나의 파일에 담는다.

```jsonc
{
  "id": "frame01",
  "name": "Duo",
  "order": 1,
  "variants": {
    "post": {
      // 좌표계 = 내보내기 규격 (1080×1350)
      "canvas": { "width": 1080, "height": 1350 },
      "assets": {
        "base": "/frames/frame01/post/base.png",
        "overlay": "/frames/frame01/post/overlay.png",
      },
      "slots": [
        // slot = 사용자가 사진 1장을 넣는 단위 (탭 대상)
        { "id": "left", "label": "왼쪽 사진" },
        { "id": "right", "label": "오른쪽 사진" },
      ],
      "placements": [
        // placement = 슬롯 사진이 실제로 그려지는 영역 (현 라인업은 슬롯:placement = 1:1)
        {
          "slot": "left",
          "rect": { "x": 312, "y": 534, "width": 202, "height": 277 },
          "mask": "/frames/frame01/post/mask-left.png", // rect는 마스크의 bbox
          "fit": "cover", // cover + 사용자 드래그/핀치줌 오프셋
        },
      ],
    },
    "story": {/* 동일 구조, canvas 1080×1920 */},
  },
}
```

- 스키마 타입은 `src/templates/schema.ts`에 TypeScript로 정의하고, JSON은 로드 시 검증한다

## 수용 기준 (Acceptance Criteria)

1. 템플릿 추가/수정이 "시안 PNG 교체 + 파생 스크립트 실행 + JSON 수정"만으로 완료된다 (컴포넌트 코드 무변경)
2. 파생 스크립트는 12장(6종×2비율) 전부에서 슬롯을 자동 추출하고, 추출 결과(슬롯 수)가 위 표와 일치한다
3. 각 템플릿의 미리보기 렌더와 시안 PNG의 픽셀 차이가 자리표시 영역 외에는 없다 (스크린샷 회귀 테스트)
4. frame02의 별 구멍·frame04의 라벨 오버레이·frame05의 낙서 겹침이 샘플(SampleNN)과 동일한 층 순서로
   재현된다
5. JSON 스키마 위반(슬롯 없는 placement 참조 등)은 로드 시점에 명시적 에러로 잡힌다
