## 배경 / 목적

v1은 "슬롯을 회색 자리표시로 칠한 통짜 불투명 PNG"에서 크로마키로 슬롯·오버레이를 추출했다.
이 방식은 구조적 한계가 있었다:

- 자리표시와 비슷한 색(무채색 그라디언트·흰 라벨)이 오추출되거나 뚫려버림 (frame04 그라디언트 유실)
- 반투명 장식(별무리 경계·그림자)을 원본 알파 없이 복원 불가 → 마스크 합성(destination-in)이
  필수가 되어 렌더 비용 증가 (스펙 03 성능 노트)

그래서 **디자이너가 레이어를 분리해 전달하는 v2 규약**으로 전환했다 (디자이너 제안 형식 채택,
2026-08-05 합의). 슬롯 위치는 색으로 선언되고, 사진 위/아래 층이 원본 알파 그대로 전달된다.

## v2 시안 전달 규약 (디자이너 → 개발)

프레임별 폴더 `docs/design/frames/<프레임명>/`에 아래 파일을 넣는다:

```
<프레임명>_<변형>_layerNN.png   # 변형 = post | story, NN = 01부터. 아래→위 순서로 쌓인다
<프레임명>_<변형>_sample_gray.png # 빈 슬롯(회색 자리표시) 상태의 완성 합성본
<프레임명>_sample.png            # 사진이 들어간 사용 예시 (post 기준 1장) — 홈 카드 미리보기 원본
```

- **캔버스**: post 4:5, story 9:16. 가로폭은 1080의 정수배 (Duo 실측 3240 = 3배). 같은 변형의
  모든 파일은 같은 크기여야 한다
- **슬롯 레이어**: 레이어 중 **정확히 1장**이 슬롯 채움을 담는다
  - 슬롯 채움 = **선명한(채도 높은) 단색** 평탄 영역. 슬롯마다 서로 다른 색, 같은 슬롯 = 같은 색
    (여러 조각이어도 같은 색이면 한 슬롯). 정확한 팔레트는 자유 — 서로 구분만 되면 된다
  - 슬롯 레이어의 나머지 내용(카드 테두리·그림자 등 "크롬")은 사진 **위**에 그대로 얹힌다
  - 배경은 투명 (채움·크롬 외 알파 0)
- **층 순서**: 슬롯 레이어보다 아래(NN 작음) = 사진 아래에 깔림, 위(NN 큼) = 사진 위에 얹힘
- **sample_gray**: 슬롯을 자리표시 회색(#D9D9D9)으로 채운 전체 합성본. **파생 자동 회귀의 QA
  기준으로만 쓴다** (런타임 에셋 아님). 권장이며, 없으면 회귀만 경고와 함께 건너뛴다
- **슬롯 순서**: 읽기 순서(위→아래, 왼→오른쪽)로 슬롯 id에 매핑된다 (스크립트 설정의 slots 배열 순서)

## 렌더링 모델 (z-순서, 2026-08-07 사용자 확정)

```
[4] overlay.webp   — 크롬(슬롯 레이어 − 채움) + 슬롯 레이어 위층들 합성 (원본 알파 그대로)
[3] (사용자 사진들) — placement 단위 배치. 사각/둥근 사각은 rect(+radius) 클립, 자유 형상만 마스크
[2] 회색 자리표시   — **코드가 rect(+radius) 데이터로 그린다.** 사진이 오면 사라지고 삭제하면 복귀
[1] base.webp      — 슬롯 레이어 **아래층들의 합성** (회색을 굽지 않는다)
```

- 자리표시를 base에 굽지 않는 이유: ① **투명 배경 사진**을 첨부하면 투명 영역으로 프레임 배경이
  비쳐야 하는데, 구운 회색이 있으면 회색이 비친다 ② 자리표시와 사진이 **같은 좌표 데이터**로
  그려지므로 어긋남이 원천적으로 불가능하다
- 크롬(테두리·그림자)은 overlay가 사진 위에 복원. 빈 칸 자리표시는 내보내기에도 포함(기존 동작 유지)
- **좌표계 = 내보내기 규격** (post 1080×1350, story 1080×1920). 파생 시 1/배율 다운스케일 —
  런타임 용량 절감 겸 좌표계 단일화
- 미리보기와 내보내기는 동일한 Konva 씬 그래프로 렌더 (AGENTS.md 원칙)

## 에셋 파생 규약 (빌드 타임 스크립트)

`scripts/derive-frames.ts` 실행 (순수 로직은 `src/lib/frame-derive.ts`):

1. **슬롯 추출**: 슬롯 레이어에서 "완전 불투명 && 채도(max−min) ≥ 60 && 정확히 같은 RGB가 캔버스의
   0.2% 이상" 픽셀을 색별로 그룹핑 → 색마다 bbox·채움비 계산, 읽기 순서로 정렬
2. **base**: 슬롯 레이어 **아래층들을 합성** 후 1/배율 다운스케일 → `public/frames/<id>/<변형>/base.webp`
3. **overlay(크롬)**: 슬롯 레이어에서 채움 픽셀을 **배율 px(1080 기준 1px)만 팽창해** 투명 처리
   (AA 잡색 제거 — base가 아래층이라 과팽창하면 그 자리에 배경이 비쳐 테두리가 얇아진다),
   위층 레이어들을 그 위에 합성, 다운스케일 → `overlay.webp`
4. **placement 분류 사다리** (rect = 채움 bbox ÷ 배율, 반올림):
   - 채움비 ≥ 99.5% → **사각 슬롯**: rect만 기록 (렌더러가 rect 클립 — 캐시·합성 생략, 스펙 03)
   - 채움이 "bbox + 균일 모서리 반지름"으로 설명되면 → **둥근 사각 슬롯**: `radius` 기록
     (모서리 결손 면적 (4−π)r²에서 역산 후 실제 픽셀과 대조 검증 — 불일치가 둘레 AA 수준을
     넘으면 기각). 마스크 파일 불필요
   - 그 외 → **자유 형상 슬롯**: `mask-<slotId>.png` 생성
5. **preview**: `<프레임명>_sample.png` 다운스케일 → `preview.webp`
6. 스크립트는 v2 폴더가 있는 프레임만 재생성한다 — 다른 프레임의 기존 산출물은 건드리지 않는다
   (v1→v2 이행기 공존)

검출 실패(슬롯 레이어 0장 또는 2장 이상, 색 수 ≠ 슬롯 수, 배율 비정수)는 명시적 에러로 중단한다.

## 템플릿 JSON 스키마

`src/templates/<id>.json` — post/story 두 변형을 하나의 파일에 담는다.

```jsonc
{
  "id": "duo",
  "name": "Duo",
  "order": 1,
  "preview": "/frames/duo/preview.webp",
  "variants": {
    "post": {
      // 좌표계 = 내보내기 규격 (1080×1350)
      "canvas": { "width": 1080, "height": 1350 },
      "assets": {
        "base": "/frames/duo/post/base.webp",
        "overlay": "/frames/duo/post/overlay.webp",
      },
      "slots": [
        // slot = 사용자가 사진 1장을 넣는 단위 (탭 대상)
        { "id": "left", "label": "왼쪽 사진" },
        { "id": "right", "label": "오른쪽 사진" },
      ],
      "placements": [
        // placement = 슬롯 사진이 실제로 그려지는 영역 (현 라인업은 슬롯:placement = 1:1)
        {
          "slot": "left",
          "rect": { "x": 312, "y": 537, "width": 206, "height": 276 },
          // radius(둥근 사각)·mask(자유 형상)는 해당 슬롯에만 존재 — 없으면 rect 클립
          "fit": "cover",
        },
      ],
    },
    "story": {/* 동일 구조, canvas 1080×1920 */},
  },
}
```

- 스키마 타입은 `src/templates/schema.ts`에 TypeScript로 정의하고, JSON은 로드 시 검증한다
- `radius`·`mask`는 **선택 필드** — radius는 둥근 사각 클립+자리표시에 쓰이고, mask가 있으면
  destination-in 합성, 둘 다 없으면 rect 클립

## 수용 기준 (Acceptance Criteria)

1. 템플릿 추가/수정이 "v2 폴더 배치 + 파생 스크립트 실행"만으로 완료된다 (컴포넌트 코드 무변경)
2. 파생 스크립트는 슬롯을 자동 추출하고, 추출 결과(슬롯 수·순서)가 위 표와 일치한다
3. 각 템플릿의 미리보기 렌더와 base+overlay 합성의 픽셀 차이가 허용치(3%) 이내다 (e2e/visual.spec)
4. 파생 시 base + 회색 자리표시(채움 마스크 그대로) + overlay 합성이 sample_gray와 일치한다
   (파이프라인 내 자동 회귀 — 불일치율 0.5% 초과 시 에러, sample_gray 없으면 경고 후 스킵.
   overlay 반투명 픽셀은 합성 순서 차이 잡음이라 판정에서 제외)
5. JSON 스키마 위반(슬롯 없는 placement 참조 등)은 로드 시점에 명시적 에러로 잡힌다
