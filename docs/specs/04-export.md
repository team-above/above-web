# 04. 내보내기 (PNG 다운로드 · 완료 화면)

- 상태: **Implemented** (2026-07-28)
- 구현 노트: done 가드는 exportUrl까지 요구(다운로드 미경유 접근·새로고침은 전부 에디터로
  리다이렉트 — 스토어 비영속이라 "미리보기 없는 done"은 존재하지 않음). `@vercel/analytics`
  `<Analytics />` 배선 완료(라우트 페이지뷰 집계) — **대시보드 Web Analytics 활성화는 사용자 몫**.
  비활성 버튼의 사유 힌트는 title 속성뿐(모바일 미표시)이나 하단 상시 힌트 문구로 갈음
- 관련: PRD §2(지표)·§4, 선행: [스펙 03](03-editor.md)(Implemented — 헤더 다운로드 버튼 자리)

## 배경 / 목적

MVP 플로우의 마지막 조각. 에디터 씬을 그대로 PNG로 저장하고, 완료를 별도 라우트로 남겨
**전환율(1차 지표)을 페이지뷰로 측정**한다 (PRD §2 — 커스텀 이벤트 없이 무료 측정).

## 요구사항

**필수**

1. 에디터 헤더의 다운로드 버튼 활성화 — **사진이 1장 이상일 때만** (빈 프레임 다운로드 방지,
   버튼 비활성 상태에서 사유 툴팁/힌트)
2. 내보내기 = **에디터 메인 레이어를 그대로 캔버스 좌표계 해상도로 래스터화**
   - Post 1080×1350 / Story 1080×1920 (현재 선택된 비율)
   - UI 배지 레이어 제외 (스펙 03에서 이미 레이어 분리됨 — 구조적 보장)
   - 사진 없는 슬롯은 base 자리표시 그대로 (frame04 확정의 일반화)
3. 파일명: `above-{frameId}-{variant}.png` (예: `above-frame01-post.png`)
4. 저장 트리거 후 `/editor/[frameId]/done`로 이동 — 완료 화면:
   - "저장했어요" 확인 메시지 + 결과 미리보기 이미지
   - CTA: "계속 편집" (에디터 복귀, 상태 유지) / "다른 프레임 보기" (홈)
5. 완료 화면 진입 = 다운로드 집계 1회 (라우트 페이지뷰)

**제외**

- 공유 시트(Web Share API), 클립보드 복사, 화질/포맷 옵션 — 검증 후 판단

## 구현 노트

- 래스터화: 메인 `Konva.Layer.toCanvas({ pixelRatio: 1 / stageScale })` → `canvas.toBlob("image/png")`
  → objectURL + `<a download>` 클릭 → revoke. (미리보기 씬과 동일 노드를 쓰므로 "보는 것=받는 것")
- done 화면의 미리보기: 내보낸 blob을 스토어에 잠시 보관(objectURL)해 이미지로 표시.
  새로고침 등으로 미리보기가 없으면 안내 문구만 (다운로드 자체는 이미 완료된 상태)
- `/done` 라우트는 클라이언트 이동(router.push) — Vercel Analytics가 라우트 페이지뷰로 집계
- 에디터 복귀 시 상태 유지: 스토어가 템플릿 단위로 유지되므로 자연 충족 (enterTemplate 가드)

## 엣지 케이스

- 인스타그램/카카오 인앱 브라우저: `<a download>`가 무시될 수 있음 → 다운로드 실패 감지는
  불가하므로, done 화면에 "사진이 저장되지 않았다면 미리보기를 길게 눌러 저장하세요" 보조 안내
- 대형 캔버스 toBlob 실패(null) → 안내 토스트, 이동하지 않음
- 사진 0장 상태에서 done 직접 접근 → 에디터로 리다이렉트 (집계 오염 방지)

## 수용 기준 (Acceptance Criteria)

1. frame01에 사진 첨부 후 다운로드 → 실제 파일이 저장되고, PNG 크기가 정확히 1080×1350
   (story 전환 시 1080×1920)이며 슬롯 위치 픽셀이 미리보기와 일치한다 (E2E, 다운로드 파일 검사)
2. 사진 1장만 채우고 내보내도 빈 슬롯의 + 배지가 결과물에 없다 (빈 슬롯은 자리표시 그대로)
3. 사진 0장이면 다운로드 버튼 비활성, done 직접 접근 시 에디터로 리다이렉트
4. 다운로드 후 `/editor/[frameId]/done` 페이지뷰가 발생하고, "계속 편집" 복귀 시 사진·조정값이
   그대로 남아 있다
5. 콘솔 에러 0 (기존 E2E 에러 수집 방식 동일)

## 테스트 계획

- 단위: 파일명 생성, 내보내기 가능 여부(사진 수) 셀렉터, done 리다이렉트 가드 로직
- E2E: 다운로드 이벤트 → 저장 파일의 PNG 헤더(크기)·픽셀 검사, 배지 미포함, done 왕복 상태 유지,
  0장 비활성. 데스크톱+모바일 양쪽

## 사용자 확인 결과 (2026-07-28)

1. **다운로드 활성 조건 = 사진 1장 이상** 확정
2. **done 화면 = 완료 메시지 + 결과 미리보기 + 계속 편집/홈 CTA** 확정

## 변경 (2026-07-28 — 기획 확정: 결과 화면 제거)

- done **화면 폐지**, 라우트는 **무화면 집계 비콘**으로 유지 — 다운로드 시 push(done) →
  즉시 replace(에디터)로 페이지뷰만 남긴다 (전환율 지표 보존, PRD §2)
- 완료 피드백은 에디터의 "저장했어요" 토스트(스토어 기반 — 라우트 왕복에도 유지)
- exportUrl(미리보기용 objectURL) 상태 제거 — 다운로드 anchor URL은 10초 후 revoke
- 트레이드오프: 인앱 브라우저용 "미리보기 길게 눌러 저장" 대체 경로 소멸 (기획 인지 필요).
  AC 2·4의 done 화면 관련 문구는 본 변경으로 대체됨
