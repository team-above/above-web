# 기능 스펙 컨벤션

새 기능/화면은 **코드보다 스펙이 먼저다.** 여기에 스펙을 작성하고 사용자 리뷰를 받은 뒤 구현한다.

## 파일 규칙

- 파일명: `NN-kebab-name.md` (예: `01-template-schema.md`) — 번호는 작성 순서
- 상태를 문서 상단에 표기: **Draft**(작성 중) → **Reviewed**(사용자 승인) → **Implemented**(구현 완료)
- **Reviewed 이전에는 구현을 시작하지 않는다**

## 스펙 구조

```markdown
# NN. 기능명

- 상태: Draft | Reviewed | Implemented
- 관련: PRD §N, 선행 스펙 링크

## 배경 / 목적

## 요구사항 (필수/선택 구분)

## UX 플로우 (화면·상호작용 단위)

## 엣지 케이스

## 수용 기준 (Acceptance Criteria — 테스트로 옮길 수 있게)

## 테스트 계획 (단위 / E2E 구분)
```

스펙이 곧 에이전트의 컨텍스트다 — 구현 세션은 해당 스펙과 PRD를 읽고 시작한다.
